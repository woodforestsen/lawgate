# 律核 LawGate · 真实法条接入方案

> 日期：2026-09-13  
> 目标：用 `data/raw/sources/chinese-laws-folk/`（已拉取，177 部法律全文）替换 `legal_facts.db` 里的 95 条手抄转录法条，使知识库变成**真实、可溯源**的法条源。

---

## 1. 现状与关键发现

- `build_sqlite.py` 的 `ingest_laws()` 已支持 `--from-raw`：从 `data/raw/{short}.txt` 读正文，调 `flk_parser.parse_law_file()` 按「第X条」切条，并标记 `source_kind=VERIFIED` / `PENDING`。
- `flk_parser.Provision` / `parse_law_file()` 接口已定义（见 `lawgate/knowledge/flk_parser.py`），专为官方 docx/PDF 转 txt 设计；CLF 的 txt 同为「章节 + 第X条」格式，**解析器天然兼容，无需重写**。
- 现有手写种子 `seed_corpus.LAW_SPECS`（~95 条 / 13 部法）将被 CLF 全集（177 部）取代；别名 / 沿革 / 主题词表（`LAW_ALIAS` / `LAW_LIFECYCLE` / `TOPIC_KEYWORDS`）保留复用。

---

## 2. 方案（新增独立脚本，最小改动）

新增 `lawgate/knowledge/ingest_clf.py`，**不动** `build_sqlite.py` / `seed_corpus.py`：

1. **备份**：`copy data/kb/legal_facts.db → data/kb/legal_facts.db.bak_{YYYYMMDD}`（回滚点）
2. **遍历** `data/raw/sources/chinese-laws-folk/*.txt`（177 个）
3. 对每个文件构造参数喂给 `parse_law_file()`：
   - `law_name` = 文件名去 `.txt`（全称，如「中华人民共和国民法典」）
   - `law_short` = 来自映射表 `CLF_LAW_SHORT_MAP`（见 §3）
   - `law_level` = 按文件名后缀判断（「法/法典」→ 法律；「条例/规定/办法」→ 行政法规/部门规章）
   - `source_db='CLF'`，`source_url` = GitHub 仓库/raw URL（NOT NULL 必填），`retrieval_date` = 今天，`validity_status` = '现行有效'（见 §4）
4. **清空并重建** `legal_provisions` / `provision_fts` / `provision_keywords`（DELETE 现有手写法条后批量 INSERT CLF）
5. **不碰** `case_registry` / `judgments`（合成案号，下一步用 JuDGE 替换）

---

## 3. law_short 映射策略

CLF 文件名是全称，而 `law_short` 用于索引 / 显示 / 通道B 精确命中。策略：

- 手工 `CLF_LAW_SHORT_MAP` 覆盖高频法（民法典→民法典、刑法→刑法、刑诉法→刑诉法、宪法→宪法、行政法→行政法 …）
- 兜底规则：去掉「中华人民共和国」前缀，取末位「法/法典/条例/规定/办法」作 short（如「反家庭暴力法」）
- 写入 `ingest_provenance` 表记录来源，便于回溯

---

## 4. validity_status

- CLF 数据为截止 2025.1.1 的现行法律文本，默认标 `现行有效`
- 对文件名 / 文末明确「已废止/已修订」的标对应状态（导入时扫描）

---

## 5. 备份与回滚

- 导入前自动备份 `legal_facts.db`
- 回滚：`copy` 备份覆盖即可
- 源数据 `data/raw/sources/chinese-laws-folk/` 始终保留，可随时重导

- **重建向量库**：`python -m lawgate.knowledge.build_vector`（或对应入口）—— 通道C 语义检索依赖 chroma，必须用新法条重建，否则检索仍是旧数据
- **重跑 E1 主对比**：此时 acc 等数字才作数
- （案号库仍是合成，E6 需 JuDGE 替换后再重测）

## 7. 风险点

1. **【最大风险】解析粒度**：CLF 部分法律可能是「单行《法名》第X条规定…」（README 示例）而非「行首第X条」。`parse_law_file` 的 `RE_ARTICLE = ^第X条` 要求「第X条」在行首；若 CLF 文件是单行无换行格式，解析可能失效。**→ 必须先小样本验证（§8）再全量**。
2. **law_short 冲突**：映射错会导致通道B（结构化精确命中）漏命中；需与 `law_alias`、用户问法对齐。
3. **数据量**：177 部法可能数万条，`provision_fts` + chroma 重建需几分钟，可接受。
4. **授权**：CLF 仓库**未明确 LICENSE**，接系统 / 参赛须标注来源、谨慎商用。

- **阶段3**：重跑 E1 验证系统端到端，更新 `data/kb/qa_report.md`

## 10. 执行记录（2026-09-14 全量导入完成）

**结果**：177 部法全部导入，`legal_provisions` 共 **14,587 行**（≈14,415 条唯一「法|条」），`provision_fts` 同步，`provision_keywords` 重建 1,237 词条，0 个空文件。备份：`data/kb/legal_facts.db.bak_2026-09-14`。`source_db='CLF'`，`source_url` 指向 GitHub 仓库，`retrieval_date=2026-09-14`，`validity_status='现行有效'`。

**实际踩坑与修复**（与 §7 预判一致）：

1. **格式双峰**（§7-1 风险坐实）：168 个文件为单行格式 `《法名》第X条规定，…`；9 个（宪法、商业银行法等）为标准「行首第X条+折行」格式。首跑只解析出 904 条 → 自动回滚（保护机制生效）。
   **修复**：`ingest_clf.py` 增加 `to_parser_lines()` 适配层——剥《法名》前缀、去「规定，」套话，标准格式行透传；按 CLF 行占比决定 `join_wrapped`。
2. **行中条首（glue）**：宪法源文件一段行内含多个条（「…义务。第三十四条 …」），第 34 条被吞进第 33 条。
   **修复**：增加 `RE_MID_ARTICLE` 切分——仅当「句号后紧跟第X条+空白」才拆行；正文引用（「本法第十四条」「第三人为债务人」）不受影响，全库 17 处「。第」残留经逐条核验均为合法正文。
3. **抽验通过**：民法典 667、反家暴法 2、消法 55、宪法 33/34 正文与官方文本一致，无书名号/套话残留。

**⚠ 数据源覆盖缺口（后续补源）**：CLF 不含 **刑法、刑事诉讼法、劳动合同法、劳动法、公司法、个人信息保护法、专利法** 等核心大法（旧婚姻法/继承法/合同法等已被民法典吸收不收，属合理）。刑法等高频法缺失会影响部分问询的通道B/C 命中率，需从其他开源源（另找 GitHub 法律语料）补充导入，`source_db` 单独标记。

**对实验数字的影响**：E1/E6 重跑前，结果仍以旧手写基线为准；向量库重建完成后 E1 才可重测（§6）。

**向量库重建（同日完成）**：

- venv 补装 `sentence-transformers==6.0.1`（torch/transformers 本就齐全），`embed_backend=bge-small-zh-v1.5`（本地权重，512 维）；chromadb 未装，走项目支持的 **NumpyStore** 精确余弦后端。
- 40,156 文档（14,451 条法条按「条」聚合 + 1,610 份合成文书 25,705 切片），CPU 编码 20.5 分钟。
- **坑**：首轮降级构建（HashingCharEmbedder）的旧向量未清空，二轮 bge 构建 `--backend auto` 走 NumpyStore 时对旧数据 **vstack 叠加**（两者同为 512 维，静默撞车，count 翻倍至 80,312）。修复：确定性截掉前 40,156 行（旧哈希向量）+ records.jsonl 对应行；重载校验 top3 无重复。
- **通道C 召回抽验**（bge 语义）：「人身安全保护令」→ 反家暴法 32/23/27 条 top3；「几倍赔偿」→ 消法 55 条（三倍赔偿）top1；「借款合同」→ top5 全是引用民法典借款条文的文书切片（法条本体仍可检，被逐字引用的文书相似度略高，属混合检索正常现象）。
- ⚠ 以后重建向量库请用 `python -m lawgate.knowledge.build_vector --backend numpy`（显式 numpy 才会先删旧 embeddings.npy/records.jsonl），不要用默认 auto。
