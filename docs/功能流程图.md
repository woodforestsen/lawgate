## 0. 先看懂一张总图：一次提问的完整旅程

在细看每个功能前，先给一张"鸟瞰图"。下面这张图把 §3–§14 串起来，
**左到右就是时间顺序**，每个方框后面括号里是细看的章节：

```mermaid
flowchart LR
    UQ["用户提问<br/>（来自 UI 或 HTTP）"] --> ROUTER

    subgraph ROUTER["§3 总路由 router.py:: _answer_events"]
        direction TB
        INT["§4 意图检测<br/>抽法名/条号/案号/主题"] --> BOK{"有查库信号<br/>且槽位齐?"}
        BOK -- "是" --> B["§5 通道 B 查库"]
        B -- "命中" --> BOUT["拼装答案<br/>（0 次检索）"]
        B -- "查无 / 槽位不全" --> GATE
        BOK -- "否" --> GATE["§8 门控<br/>草稿→u 信号→比阈值 τ_b"]
        GATE -- "u ≤ τ_b" --> A["通道 A<br/>直接生成（0 次检索）"]
        GATE -- "u > τ_b" --> RETRIEVE["§10 检索一次"]
        RETRIEVE --> C["通道 C<br/>检索增强生成（1 次检索）"]
    end

    BOUT --> LLMX
    A --> LLMX["§11/§12 大模型生成<br/>（API 或本地权重，先查 §13 缓存）"]
    C --> LLMX
    LLMX --> TRACE["统一 trace 决策记录<br/>（通道/u/τ/槽位/来源/耗时…）"]
    TRACE --> OUT["§14 SSE 或 JSON 返回<br/>§15 UI 双栏渲染"]
```

> **一张纸记住系统**：能查库的（法条/案号）→ 通道 B；查不了再让模型"打 20 字草稿"
> 看它心不心虚（u），心虚（u 大）→ 检索一次再答（通道 C），不心虚 → 直接答（通道 A）。
> 每一问都附一份 trace，写清"为什么这么路由、引用了哪条法、链接在哪"。

## 1. 知识库构建（法条入库）

**入口命令**（README §1 第 2 步）：

```powershell
python -m lawgate.knowledge.build_sqlite
```

**产物在哪**：`data/kb/legal_facts.db`（法条+案号+沿革+词典的 SQLite 库）、
`data/raw/*.txt`（种子语料落盘）、`data/kb/qa_report.md`（验收报告）、
`data/kb/manual_audit.csv`（人工抽验清单）。

```mermaid
flowchart TD
    A0["入口：python -m lawgate.knowledge.build_sqlite<br/>build_sqlite.py::main"] --> A1{"参数?"}
    A1 -- "默认" --> A2["全量重建：种子语料 LAW_SPECS<br/>seed_corpus.py（人工录入的关键条文）"]
    A1 -- "--from-raw" --> A2b["从 data/raw/*.txt 读入<br/>（真实导入通道，供 FLK 官方原文覆盖）"]
    A1 -- "--report" --> A9["只重算 qa_report.md，不动库"]
    A2 --> A3["write_raw_files()<br/>种子语料逐法落盘 data/raw/*.txt<br/>+ sources.json（每条的溯源状态）"]
    A3 --> A4["create_schema()<br/>执行 schema.sql + schema_ext.sql<br/>（法条表 / FTS / 案号库 / 文书 / 沿革 / 词典 / 溯源表）"]
    A4 --> A5["清空 legal_provisions / provision_fts / provision_keywords"]
    A5 --> A6["逐法解析入库：flk_parser.py<br/>① 条号状态机 parse_law_text（中文条号 cn2int）<br/>② 审计 audit.py::audit_law：条号连续性 + 100% 往返一致<br/>③ 民法典特判 EXPECTED_MAX=1260 条"]
    A6 --> A7["案号真值库：seed_cases.py::generate_cases<br/>合成案号 + 合成文书（data_source=SYNTHETIC，必须披露）"]
    A7 --> A8["沿革表 / 替代映射 / 词典入库<br/>（law_lifecycle、supersede_map、law_alias、topic_keyword）"]
    A8 --> A9
    A9 --> DONE["产物：legal_facts.db + qa_report.md<br/>+ manual_audit.csv + build_summary.json"]
```

**验收怎么查**：打开 `data/kb/qa_report.md`，每部法律有"覆盖状态（全量/部分）+
审计结果（条号连续、无跳号）"；`manual_audit.csv` 是 120 条抽验清单。
**诚实披露**：当前库内法条全部是 `MANUAL_TRANSCRIPT`（人工录入、未与官方原文逐字比对），
案号库全部 `SYNTHETIC`——这两条必须写进 `docs/DATA_GAP.md`（已写）。

## 2. 向量库构建

**入口命令**：

```powershell
python -m lawgate.knowledge.build_vector
```

**产物在哪**：`data/kb/chroma/`（ChromaDB 持久化目录；numpy 兜底则是
`embeddings.npy` + `records.jsonl`）+ `data/kb/vector_build.json`（规模与编码器溯源）。

```mermaid
flowchart TD
    V0["入口：python -m lawgate.knowledge.build_vector"] --> V1["collect_records()<br/>从 legal_facts.db 取两类文档："]
    V1 --> V1a["① 法条：按『条』聚合（GROUP_CONCAT 把一条的全部款项拼成一段）<br/>id = lp_法名_版本_条号<br/>meta: type=provision / law / article / validity_status / url"]
    V1 --> V1b["② 文书：judgments 表（前 2000 条）<br/>每篇文书已分块（300字/50字重叠，见 §2 前置）<br/>id = jd_案号_块号<br/>meta: type=judgment / case_no / cause"]
    V1a --> V2["get_embedder()（knowledge/embed.py）<br/>优先 models/bge-small-zh-v1.5（512维）<br/>加载失败 → HashingCharEmbedder（字符 n-gram 哈希，纯 numpy 离线兜底）<br/>⚠️ 查询侧要加指令前缀『为这个句子生成表示以用于检索相关文章：』，文档侧不加（bge 既定用法）"]
    V1b --> V2
    V2 --> V3["get_store()（knowledge/store.py）<br/>优先 ChromaStore（chromadb 持久化）<br/>失败 → NumpyStore（精确余弦检索）"]
    V3 --> V4["按 64 条一批编码 → vstack 成矩阵<br/>store.add(ids, docs, metas, embeddings)"]
    V4 --> V5["写 vector_build.json<br/>（n_docs / n_provisions / n_judgment_chunks / 编码器名 / 后端 / 耗时 / 硬件）"]
    V5 --> DONE["产物：data/kb/chroma/（当前实测 1295 文档、512 维、37.8s）"]
```

**验收怎么查**：`data/kb/vector_build.json` 里的 `embed_backend` 必须是
`bge-small-zh-v1.5`（若写 `HashingCharEmbedder` 说明语义模型没加载成功，检索召回会明显变差）；
`docs/quickcheck.txt` 里有向量库条数的自检。

## 3. 总路由：一次提问怎么走

**源码位置**：`lawgate/router.py` 的 `LegalGateRouter._answer_events()`
（`answer()` 与 `answer_stream()` 的**唯一**实现，非流式只是"整段当一个 delta 发"，
保证界面与接口永远同一个口径）。

**触发路径**：HTTP `POST /chat`（同步）→ `answer()`；HTTP `POST /chat/stream`
（SSE）或 UI 提问 → `answer_stream()`。

```mermaid
flowchart TD
    R0["入口：_answer_events(query, history, meta, stream)"] --> R1["读 meta.temporal.as_of<br/>（时效题的评估日期；只取这一个无害字段）"]
    R1 --> R2["§4 detect_intent(query, history, db_path)<br/>→ Intent{hit_provision, hit_case_no, slots_complete, route_b_reason}"]
    R2 --> R3{"b_eligible?<br/>= hit_provision or hit_case_no or slots_complete<br/>且未开消融开关 disable_channel_b"}
    R3 -- "否（纯概念/普通问题）" --> R6
    R3 -- "是" --> R4["§5 通道 B：self.B.run(slots, query, as_of)<br/>返回 dict（命中）或 None（查无/槽位不全）"]
    R4 -- "命中" --> R5["yield stage(channel_b)<br/>yield delta（整段，通道B没有token流）<br/>yield done{answer, trace(channel=B, n_retrieval_calls=0, draft_source='channel_b（未取草稿）')}<br/>【直接结束】"]
    R4 -- "查无" --> R6["§8 门控"]
    R6 --> R7["stats = self.draft.draft_logprobs(query, history, k=k_draft=20)<br/>（草稿来源链：§8-2，失败自动换源并留痕）"]
    R7 --> R8["u_signal = SIGNALS[opt.signal](stats)<br/>默认 margin：u = exp(−mean(前8位 top1−top2)) ∈ [0,1]"]
    R8 --> R9["bucket = meta.bucket（若有）否则 classify_bucket()<br/>b1 概念 / b2 法条 / b3 案例 / b4 多轮（§9 定义）"]
    R9 --> R10["u_cplx = complexity_score(query, slots, history, category)<br/>（§8-3 确定性复杂度评分）"]
    R10 --> R11{"router_mode（默认 hybrid）"}
    R11 -- "hybrid：bucket ∈ signal_buckets=('b2',)" --> R12a["u = u_signal（神经信号），gate_source=neural_signal"]
    R11 -- "hybrid：bucket ∈ b1/b3/b4" --> R12b["u = u_cplx（复杂度），gate_source=complexity"]
    R11 -- "signal（消融）" --> R12c["全部桶 u = u_signal"]
    R11 -- "complexity（降级）" --> R12d["全部桶 u = u_cplx"]
    R12a --> R13
    R12b --> R13
    R12c --> R13
    R12d --> R13["τ_b = taus[bucket] × tau_scale<br/>（§9 校准值，configs/thresholds.json）"]
    R13 --> R14{"u > τ_b ?"}
    R14 -- "否" --> R15["通道 A：context=None，0 次检索"]
    R14 -- "是" --> R16["先 yield stage(retrieval)（告诉前端『要去检索了』，避免黑屏等待）<br/>§10 rr = retriever.retrieve(query, top_k=8, rerank=True)<br/>context = rr.context（拼好的参考资料文本）"]
    R15 --> R17["yield stage(generate，带 channel/u/tau_b/bucket)"]
    R16 --> R17
    R17 --> R18{"stream?"}
    R18 -- "是（UI / SSE）" --> R19["for piece in llm.generate_stream(query, history, context, max_tokens=192):<br/>每个 piece yield 一个 delta<br/>answer = 拼接后 strip（done 时以拼接结果为准）"]
    R18 -- "否（/chat、评测）" --> R20["answer = llm.generate(...)（整段，§11/§12）<br/>整段当一个 delta 产出"]
    R19 --> R21
    R20 --> R21["组装统一 trace（§0 总图右侧）<br/>yield done{answer, trace}"]
```

**trace 里每个字段从哪来**（答辩被问到"这个数怎么来的"时对照此表）：

| 字段 | 来源 |
|---|---|
| `channel` | R14 的判定结果（A / C；通道 B 路径写 "B"） |
| `u` / `u_signal` / `u_complexity` | R8（神经信号）、R10（复杂度）、R11–R13（实际采用的那个） |
| `gate_source` | R11 分支里写死的 `neural_signal` / `complexity` |
| `tau_b` / `bucket` | R9（分桶）、R13（校准值 × tau_scale） |
| `complexity_features` | R10 各特征维度逐项值（§8-3 的 7 个特征） |
| `slots` / `slots_inherited` | §4 槽位抽取 + 继承（只继承上一轮**通道 B 确认过**的 topic/law_short） |
| `validity_status` / `case_verify` / `source_url` / `must_show_warning` | 仅通道 B 命中时填充（§5/§6/§7） |
| `draft_source` / `draft_attempts` / `draft_seconds` / `draft_text` | §8-2 草稿来源链的留痕（"这条 u 到底是谁给的"） |
| `n_retrieval_calls` | 通道 A=0，通道 C=1，通道 B=0 |
| `latency_ms` | R0 到 done 的端到端耗时 |

## 4. 意图检测与槽位抽取（§3 的第 1 步）

**源码位置**：`lawgate/gate/intent.py::detect_intent()`，**全确定性**（正则+词典，不用 AI）。
词典优先读数据库（`law_alias` / `topic_keyword` 表），读不到用内置兜底表。

```mermaid
flowchart TD
    I0["输入：query + history（可空）"] --> I1["① 案号：extract_case_no(query)<br/>（底层走 knowledge/judgment_parser.parse_case_no，D31 单一出处）"]
    I1 --> I1a{"解析成功?"}
    I1a -- "是" --> I1b["hit_case_no=True<br/>slots.case_no_raw=规范化案号, case_no_parsed=年份/法院/类型/序号"]
    I1a -- "否" --> I1c{"形似案号（含 (年份) 前缀）<br/>且类型代字是编造词（如『测』）?"}
    I1c -- "是" --> I1d["hit_case_no=True, parsed={}<br/>（后面由 §6 判为『格式非法』）"]
    I1c -- "否" --> I2
    I1b --> I2["② 法律名：按『长别名优先』在词典里扫<br/>（『民法典时间效力规定』不会被『民法典』截断）→ slots.law_short"]
    I2 --> I3{"③ 条号：两种形态<br/>a. RE_ARTICLE_REF：『第X条 第Y款 (Z)项』（中文/阿拉伯数字都行）<br/>b. D26-1 补的口语形态：法名后紧跟数字『婚姻法32』『公司法47』<br/>  双守卫：数字必须整体匹配（不把『2021年』啃成 202 条）+ 排除 1900–2100 年份"}
    I3 -- "a 或 b 命中" --> I4["slots.article_no=条号（及款/项）, hit_provision=True"]
    I3 -- "都不命中" --> I5
    I4 --> I5["④ 主题词：topic_keyword 表（8 大主题 × 若干关键词）→ slots.topic"]
    I5 --> I6["⑤ 两个标志：<br/>provision_seeking：出现『哪条/依据/法条/有哪些/怎么规定…』= 要条文（D26-3 补了『有哪些』）<br/>temporal_query：出现『现在/现行/废止/还有用吗…』= 时效问句"]
    I6 --> I6a{"topic ∧ provision_seeking（主题+要条文，无条号）?"}
    I6a -- "是" --> I6b["hit_provision=True（P4 路线）"]
    I6a -- "否" --> I6c{"temporal_query ∧ law_short?"}
    I6c -- "是" --> I6d["hit_provision=True（P2/P3 路线）"]
    I6c -- "否" --> I7
    I6d --> I7["⑥ 槽位继承：倒扫 history，只认上一轮 trace.channel=='B'<br/>且 slots 里已确认的 topic / law_short（不从未确认轮次抓词）"]
    I7 --> I8["⑦ 完整性判据（slots_complete，D10/D12 修正后）：<br/>case_no / (law+article) / law_validity / (topic+provision_seeking 且无条号)<br/>四者命中其一 → slots_complete=True 并记 route_b_reason"]
    I8 --> DONE["返回 Intent{hit_provision, hit_case_no, slots, slots_complete, route_b_reason}"]
```

**三个关键修正（为什么不是"直接照手册写"）**：

- **D10**：手册的 `topic and not article_no` 会把"什么是离婚冷静期"（主题词命中）
  误送进通道 B；现在要求主题路线**额外**出现法条索取标记才进 B。
- **D12**：补了"法律名+时效问句"（"担保法现在还有用吗"）→ P3 效力询问路径。
- **D26-1**：口语"婚姻法32"不写"第…条"，补第二条正则 + 两道防误抓守卫。

## 5. 通道 B 的四条路径（§3 的 B 分支）

**源码位置**：`lawgate/channel/b_structured.py::ChannelB.run()`，**0 次检索**，
全部是查 SQLite 拼装。**连接按线程惰性建立**（D28：sqlite 连接不能跨线程，
FastAPI 线程池里多线程共享一条连接会直接 `ProgrammingError`）。

四条路径是**顺序短路**的：命中哪条就走哪条，命中即返回；全不命中才返回 `None`（回落到门控）。

```mermaid
flowchart TD
    B0["输入：slots（§4 抽的）+ raw_query + as_of（默认今天）"] --> B1{"P1：案号<br/>slots.case_no_parsed 或 case_no_raw 非空?"}
    B1 -- "是" --> B1a["§6 verifier.verify(parsed, claimed_cause)<br/>claimed_cause 优先从提问里扫案由词表（case_registry 的 cause_action，长词优先，D26-2）<br/>slots.topic 只做兜底（它是主题标签，粒度≠案由）"]
    B1a --> B1b["拼装答案 = 核验结论 v.detail<br/>+（通过且库里有）文书信息：法院｜案由｜裁判日期<br/>+（合成库必须加）⚠️ 数据溯源警示：本案号来自合成库 SYNTHETIC"]
    B1b --> DONE["返回 {answer, trace(channel=B, case_verify), must_show_warning=(未通过), provision=None}"]

    B1 -- "否" --> B2{"P2：法条+时效<br/>law_short ∧ article_no?"}
    B2 -- "是" --> B2a["§7 temporal.check_provision(law, article, as_of)"]
    B2a --> B2b{"is_safe?"}
    B2b -- "否（已废止/已修订/尚未生效）" --> B2c["_compose_warning()：<br/>① 警示语 ② 替代条文现行原文+来源（replacement_map → fetch_current）<br/>③ 替代说明 ④ 法律沿革链<br/>must_show_warning=True, provision=None"]
    B2b -- "是" --> B2d["temporal.fetch_current(law, article)<br/>= legal_provisions 按 version DESC 取最新"]
    B2d --> B2e{"查到?"}
    B2e -- "查无此条" --> MISS["trace.validity_status='查无此条'，return None<br/>（⚠️ 回落门控走通道 A/C——D26-1 修复前的老代码会静默降级，现在 trace 里写明）"]
    B2e -- "有" --> B2f["只保留最新 version 的款项行 → _render 拼装：<br/>《法名》第X条 原文…（来源：url）"]
    B2f --> DONE

    B2 -- "否" --> B3{"P3：法律效力询问<br/>law_short ∧ (law_validity_query<br/>或 temporal_query 且无 topic)?"}
```

## 8. 门控（§3 的核心）：u 从哪来、跟谁比

门控由**三个部件**组成：① 草稿（取 token 级 logprob 分布）、② 神经信号（把分布压成一个 [0,1] 的 u）、
③ 复杂度评分（确定性备选闸门）。三者的关系是**可配置**的（`RouterOptions.router_mode`）。

### 8-1 部件总览

```mermaid
flowchart LR
    subgraph 草稿来源链["§8-2 draft_logprobs（取前 k=20 个 token 的 top-20 分布）"]
        L["local：本机 Qwen2.5-0.5B（默认）"] --> API["api：回答模型的 API logprobs（思考模式）"]
        API --> RULE["rule：确定性伪分布（ExtractiveLLM 兜底）"]
    end
    草稿来源链 --> SIG["§8-2' 神经信号 u_signal = exp(−mean(前8位 top1−top2)) ∈ [0,1]"]
    Q["query + slots + history + category"] --> CPLX["§8-3 复杂度评分 u_cplx ∈ [0,1]（7 个特征加权）"]
    SIG --> MODE{"router_mode"}
    CPLX --> MODE
    MODE -- "hybrid（默认）：b2 用神经，b1/b3/b4 用复杂度" --> U["实际 u"]
    MODE -- "signal（消融）：全桶神经" --> U
    MODE -- "complexity（降级）：全桶复杂度" --> U
    U --> CMP{"u > τ_b ?"}
    CMP -- "是" --> C["通道 C（检索 1 次）"]
    CMP -- "否" --> A["通道 A（直答）"]
```

**为什么 b2 用神经、其他桶用复杂度**（`gate/complexity.py` 模块注释里的 E0 结论）：
全桶汇总 AUC 只有 0.557（红灯），但**分桶**看：b2 法条查询 AUC=0.734（信号有效），
b1 概念/b4 多轮 AUC 反向（标签由类别规则决定，与"模型心不心虚"无关甚至反相关）。
这是辛普森悖论——按桶各用各的闸门才是对的。

### 8-2 草稿来源链（回答模型换 API 后 u 到底谁给）

**源码位置**：`lawgate/channel/draft_source.py::DraftSourceChain`（D30 新增）。

```mermaid
flowchart TD
    D0["draft_logprobs(query, history, k)"] --> D1{"按 build_draft_source() 的配置排的来源顺序"}
    D1 -- "回答模型是本地（hf/rule）" --> D2["单源 answer_model：<br/>草稿与正式生成共享同一模型（手册原设计，prefill 成本不翻倍）"]
    D1 -- "回答模型是 API（deepseek）<br/>且 draft_source=auto（默认）" --> D3["① local：本机 Qwen2.5-0.5B（LazySource 惰性加载，~2GB）<br/>成功 → 返回 DraftStats(source='local')"]
    D3 -- "失败/未配置" --> D4["② api：回答模型自己的 logprobs（**强制思考模式**，因为关思考时是占位符 0.0/-9999）<br/>拿到后跑退化检测 degenerate_reason()：<br/>选中 token 全 0.0 或候选过半 ≤ -9998 → 抛 DegenerateLogprobs"]
    D4 -- "退化/失败" --> D5["③ rule：ExtractiveLLM 确定性伪分布<br/>（trace 里写 source=rule，明确不是神经信号）"]
    D3 --> D6["每一步都 append 到 attempts[]：<br/>{source, ok, seconds, error?}<br/>最终写进 trace.draft_attempts"]

    D5 --> D6
```

**为什么默认 local 优先而不是"语义最贴的" api**（模块文档里的实测对照）：

| 查询 | u(API 草稿) | u(本机 0.5B) |
|---|---|---|
| 什么是离婚冷静期？ | 0.0000 | 0.0161 |
| 《合同法》第52条… | 0.0001 | 0.0263 |
| （2022）沪01民终12345号… | 0.0012 | **0.3632** |
| 担保法现在还有用吗？ | 0.0000 | 0.0790 |

API 的 logprobs 给的是**套路化推理前缀**的分布（模型在上面极度自信，裕度 9–11 nats），
算出的 u 全贴着 0，**没有区分度**——不是"取不到"，而是"取到了但塌缩了"，更隐蔽。
本机 0.5B 的 u 有量级差异（案号题最高 0.363），因此作为默认。


## 13. 内容寻址缓存（所有后端的公共底座）

**源码位置**：`lawgate/cache.py::GenCache`。

```mermaid
flowchart TD
```

```mermaid
flowchart TD
    A0["服务启动：ROUTER 为进程内单例、**惰性**（首请求才 build_context() 加载模型+向量库，加锁防并发重复加载）"] --> A1{"请求?"}
    A1 -- "GET /health" --> A2["provenance()（硬件/模型/精度）+ llm 块（实际生效的后端/模型/Key 有无/思考模式/草稿源）+ cache.stats()"]

    A4 --> A5["内部生成器：逐帧 _sse_frame(event, data)<br/>stage → delta* → done[→ error]（异常也成帧，前端不会只看到『连接断了』）<br/>media_type=text/event-stream; charset=utf-8（无 charset 时浏览器按 ISO-8859-1 解中文=乱码，本项目踩过）"]
```

**SSE 帧协议**（`/chat/stream`，前端/`scripts/check_stream.py` 都按这个写）：

| 帧 | 数据 | 说明 |
|---|---|---|
| `stage` | `{stage: channel_b/retrieval/generate, channel, u, tau_b, bucket, decision}` | "正在做什么"，通道 B 命中/检索前/生成前各发一次 |
| `delta`* | `{text: 增量}` | 通道 B 只有**一整段**（查库拼装没有 token 流，不假装逐字）；A/C 逐 token |
| `done` | `{answer: 权威全文, trace, provision}` | **收口以它为准**，delta 拼接可能有首尾空白差 |
| `error` | `{message: "异常类: 信息"}` | 异常也成帧 |

## 15. Gradio 双栏演示界面（两栏同时流式）

**源码位置**：`lawgate/api/ui.py::respond_stream()`。

**设计要点**：左栏（无门控直答）与右栏（律核）各要十几秒 CPU 生成。若串行，
"先左后右"会让另一栏一直空白。所以**左栏丢后台线程写队列，右栏事件流在主线推进，
主线每个事件间隙顺手取左栏分片**——两栏同时长出来。

```mermaid
flowchart TD
    U0["用户点『提问』（或预设按钮）"] --> U1["respond_stream(query, history, as_of)（生成器：Gradio 每次 yield 推一帧给浏览器）"]
    U1 --> U2["ensure_loaded()：首问才加载（build_context + RouterOptions(max_new_tokens=gen_max_tokens())<br/>——把生成长度在构造 router 时定死，右栏取值与左栏显式传入的同一个数，两栏同长由构造保证，D28-3）"]
    U2 --> U3["mt = column_max_tokens(router)（右栏真实值，默认 192，-UiMaxTokens 可改，两栏一起变）"]
    U3 --> U4["启动左栏后台线程 _left_worker：<br/>base_llm.generate_stream(query, history, context=None, max_tokens=mt)<br/>每个分片 → queue 写 ('delta', piece)；结束写 ('end')"]
    U4 --> U5["主线循环 router.answer_stream(query, history, meta) 的每个事件："]
    U5 --> U6["_drain_left()（取光队列里的左栏分片）"]
    U6 --> U7{"事件类型?"}
    U7 -- "stage" --> U8["status_html 更新：『⚖️ 通道B 查库中』『🔎 通道C 检索中(u>τ)』『✍️ 通道A/C 生成中』"]
    U7 -- "delta" --> U9["right_buf += 增量"]
    U7 -- "done" --> U10["right_buf = done.answer（权威全文覆盖分片拼接）<br/>trace = done.trace；provision → 尾部『【结构化命中】法名条号列表』"]
    U8 & U9 & U10 --> U11{"节流：距上次 flush ≥0.06s 或事件是 done/stage?"}
    U11 -- "是" --> U12["_snapshot：左栏=left_buf / 右栏=right_buf+provision / trace_html=build_trace_html(trace)（通道/门控来源/决策/u/τ/桶/槽位/继承/时效/核验/来源/延迟/检索命中/草稿来源，D30 起必须显示草稿来源行）<br/>yield (left, right, trace_html, history, 状态行)"]
    U11 -- "否" --> U13["本轮不 flush（缓存命中时会一次涌出大量分片，不节流会打爆 WebSocket）"]
    U12 --> U5
    U13 --> U5
    U5 -- "右栏流结束" --> U14["左栏可能还在生成：while not left_done 继续 q.get(timeout=0.2) 取尾巴（否则界面停在半句话）"]
    U14 --> U15["最终 yield（final=True）：history 追加本轮 {query, answer=右栏, trace}<br/>（带 trace —— 下一轮 HTTP/UI 多轮槽位继承才认它，D26-4）"]
```

**Trace 面板渲染**（`build_trace_html`）：约 20 行表格 + 命中时效/核验风险时顶部
橙色警示条（`must_show_warning`）+ 检索命中 `<details>` 折叠区。
