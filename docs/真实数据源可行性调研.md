# 律核 LawGate · 真实数据源可行性调研

> 日期：2026-09-13
> 背景：当前 `data/kb/` 知识库的法条为 `MANUAL_TRANSCRIPT` / `PENDING_FLK_VERIFICATION`（手抄转录、未官方核验），案号库 600 条为 `SYNTHETIC`（合成）。这导致所有"真实准确率"数字（E1 acc、E6 PRF）作废，系统只能当 demo。
> 目标：**换真实数据源重建 `data/kb/` 并重评 E1/E6**，代码与架构基本不动。
> 结论先行：**最现实的入口是 GitHub 开源数据集（法条 + 评测），而不是硬啃裁判文书网的反爬。**

---

## 1. 本机环境约束（已知）

| 约束 | 影响 |
|---|---|
| Google 系不可达 | 不影响国内站点 |
| HuggingFace 被中间层劫持 | **不能从 HF 直下数据集**（如 `legal-corpus-public-sanitized` 等不可行） |
| GitHub 可直连 | `git clone` / `curl raw` 可用 → **开源数据集是首选入口** |
| 国内 `.gov.cn` 一般可直连 | 难点在反爬 / 会话验证，不在连通性 |

## 3. 推荐修复路线（按可行性排序）

1. **法条**：优先用 `Chinese-Laws-folk`（GitHub 直拉，结构化带条号）→ 改造 `seed_corpus.py` / `flk_parser.py` 接入真实源。
2. **案号 / 文书**：用 `JuDGE` 开源判决（带引用法条索引）替代合成案号库；裁判文书网仅作补充且需谨慎合规。
3. **评测集**：用 `Legal-DC` 替换 `data/benchmark`。
4. **重建 + 重测**：重跑 `build_sqlite.py` + `build_vector.py` 重建 `data/kb/` → 重跑 E1/E6（此时数字才作数）。

---

## 4. 合规边界

- 仅使用**公开 / 开源**数据、限定**研究用途**；文书中个人敏感信息务必**脱敏**。
- 裁判文书网爬取属灰色地带，学生项目优先走开源 / 官方导出，避免高频爬取与商用。
